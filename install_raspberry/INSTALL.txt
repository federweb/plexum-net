============================================================
  NodePulse — Raspberry Pi Installation Guide
============================================================


REQUIREMENTS
------------
- Raspberry Pi 3, 4 or 5 (Pi 4 with 2GB+ recommended)
- Raspberry Pi OS 64-bit, Bookworm or newer (Lite is fine)
- A normal user with sudo (the default "pi" user works)
- Internet access — no port forwarding, no public IP needed

Do NOT run the installer as root.


------------------------------------------------------------
  INSTALL
------------------------------------------------------------

1. Copy install_raspberry/ onto the Pi:

    scp -r install_raspberry pi@raspberrypi.local:~/

2. SSH into the Pi:

    ssh pi@raspberrypi.local

3. Run the installer as your normal user:

    cd ~/install_raspberry
    bash rpi-setup.sh

   The script will:
   - Install PHP, nginx, Python, Node and cloudflared (arm64)
   - Download the apps bundle into ~/www/
   - Configure an unprivileged nginx on port 8080 (prefix ~/nginx/)
   - Generate the RSA node identity in ~/.nodepulse/
   - Install the ~/bin commands and a systemd unit

   The "npm install peer" step takes several minutes on a Pi.
   That is normal — let it finish.

   Wait for "SETUP COMPLETE!" before continuing.

4. Open a new shell so ~/bin lands on your PATH:

    exit
    ssh pi@raspberrypi.local


------------------------------------------------------------
  START
------------------------------------------------------------

There are two ways to run the node, and you should end up
using the second one. Never both at once: they compete for
port 8080 and the loser dies on startup.


1) BY HAND — for the first test only

    start-server

Everything runs in the foreground of your shell. The public
Cloudflare tunnel URL appears in the output once cloudflared
connects; open it in a browser to confirm the node works.

This mode dies when you close the SSH session, and nothing
comes back after a reboot or a power cut. Use it once, to see
that the stack is healthy, then move on.


2) SUPERVISED BY SYSTEMD — how a Pi is meant to run

rpi-setup.sh installed /etc/systemd/system/nodepulse.service
but left it disabled, so this step is yours to take:

    stop-server                          # kill the manual run first
    sudo systemctl enable --now nodepulse

    systemctl is-enabled nodepulse       # must print: enabled
    journalctl -u nodepulse -f           # follow the tunnel URL

"enable" writes a symlink under multi-user.target.wants/. It
lives on the SD card, so it survives reboots and power cuts:
pull the plug, plug it back in, and systemd starts the node on
its own once the network is up — no login, no SSH session, no
"linger" needed. "--now" just also starts it immediately so
you do not have to reboot to test.

The unit stays alive as long as the tunnel does, because
start-server ends with the nodepulse supervisor loop in the
foreground. If cloudflared crashes, that loop retries on its
own (5 times, 30s..300s backoff). If it gives up entirely,
Restart=always brings the whole stack back 60 seconds later.

From here on, manage the node through systemd, not ~/bin:

    sudo systemctl start nodepulse       # was: start-server
    sudo systemctl stop nodepulse        # was: stop-server
    sudo systemctl restart nodepulse
    journalctl -u nodepulse -f           # was: the shell output

Two things change once systemd owns the node:

- The tunnel URL is no longer on your screen. It goes to the
  journal instead:
      journalctl -u nodepulse -b | grep -i trycloudflare
- The quick tunnel URL is different after every restart. The
  node comes back by itself, but at a new public address —
  which is exactly what the announce to the seeds is for. An
  old bookmark will not follow it; the Plexum network will.


------------------------------------------------------------
  OTHER COMMANDS
------------------------------------------------------------

  stop-server      Stop all services
  server-status    Services + SoC temperature, throttling, memory
  run-looped -12   Restart the whole stack every 12 hours

stop-server stays useful as an emergency hammer, but under
systemd you rarely call it: systemctl stop already runs it via
ExecStop. run-looped is for the by-hand mode only — with the
unit enabled, Restart=always already covers it, and running
both just fights over port 8080.

If server-status shows a throttling value other than 0x0, the
Pi is being throttled — almost always an underpowered power
supply. It is the usual cause of a node that degrades slowly.


------------------------------------------------------------
  SECURITY
------------------------------------------------------------

This is a persistent machine, not a throwaway distro, and the
tunnel exposes it publicly.

- Everything runs as your normal user, never as root.
- The Terminal and PulseTerminal apps hand out a shell as that
  user. On Raspberry Pi OS the default user often has
  passwordless sudo — lock it down:

    sudo passwd -l pi

  or install NodePulse under a dedicated unprivileged account.
- Set the auth_gate password on first access, BEFORE sharing
  the tunnel URL. Anything not behind auth_gate is public.


------------------------------------------------------------
  TROUBLESHOOTING
------------------------------------------------------------

  Package install failed
    See ~/tmp/apt-install.log for the real apt error.

  PHP execution failed / 502
    See ~/nginx/logs/error.log — the unprivileged nginx logs
    there, not in /var/log/nginx.

  Port 8080 already in use
    ss -ltnp | grep 8080
    The packaged nginx service is disabled by the installer;
    something else is holding the port.

  Tunnel keeps crashing
    nodepulse retries 5 times (30s..300s backoff) then stops.
    Under systemd the unit restarts it 60s later on its own;
    by hand, re-run start-server.

  Nothing came back after a reboot
    systemctl is-enabled nodepulse
    If it prints "disabled", the enable step was never done —
    see START, part 2. If it prints "enabled" but the node is
    down, read the journal for this boot:
        journalctl -u nodepulse -b


------------------------------------------------------------
  UNINSTALL
------------------------------------------------------------

  sudo systemctl disable --now nodepulse
  sudo rm /etc/systemd/system/nodepulse.service
  sudo systemctl daemon-reload
  pm2 delete peerserver; pm2 kill
  rm -rf ~/www ~/nginx ~/bin ~/tmp ~/services ~/.nodepulse
  rm -f ~/.server-mode ~/.nginx-bin
  sudo rm -f /etc/php/*/cgi/conf.d/nodepulse.ini

Deleting ~/.nodepulse/ destroys the node identity: the node
rejoins the network as a brand new node_id. Back it up first
if you want to keep it.
